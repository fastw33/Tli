# Global scroll motion and freight imagery

Page navigation uses a content fade with a small upward arrival in `usePageTransitions` and `NavigationProvider`. `SiteLink` lets Next navigate directly with its normal prefetching and link behavior. Departure briefly softens the content to 75% opacity over 120 ms without waiting or persistent fill. After scroll/focus settle, `RouteReady` fades content from zero opacity while moving it up 32 px over 480 ms (20 px / 420 ms on mobile). The fixed navigation stays stationary: ordinary pages animate their main content, while home animates only the explicitly marked hero copy because its menu is embedded inside main. CSS provides the opacity arrival on full document/language changes without changing anchor geometry. Same-page anchors do not animate; back/forward retains saved scroll positions. Reduced motion disables animation and rapid navigation cancels previous animations. No covering panel, viewport snapshot, render-blocking promise or animation timer is used.

`ScrollAnimations.tsx` is the sole AOS owner, mounted in the shared English/Spanish `SiteLayout`. It initializes the existing AOS 2.3.4 package once and refreshes its registry on route changes, element insertion/removal, glossary visibility changes, image loads and details expansion. Navigation, dialogs, sticky elements and form contents are excluded from automatic animation assignment. The global CSS keeps focused content usable and provides no-JavaScript, initialization-failure and reduced-motion fallbacks.

New blocks already visible on route entry receive a starting frame before AOS refreshes, so their entrance can be seen instead of being completed synchronously during setup. Programmatically focused headings and focused interactive content remain visible. Resize refreshes also recalculate the stagger to match the current grid column count.

Entry animations use 950 ms easing, an 80 px trigger offset, delays capped at 300 ms, and `once: false`. Automatically registered articles use a zoom-and-rise entrance; other blocks fade upward. Desktop motion starts 72 px lower at 90% scale for cards, reduced to 48 px / 94% on mobile. Grid cards enter at 150 ms intervals across each visible row; one-column mobile grids have no extra delay. Featured service images settle from a subtle 107% crop over 1200 ms. Installed AOS 2 does not implement the `mirror` option advertised by newer type declarations, so an IntersectionObserver adds `data-aos-exited` after a block completely leaves the top of the viewport; the stylesheet supplies a 48 px upward exit with a slight scale reduction. Re-entering the viewport clears it. This provides repeatable entry and exit without swapping libraries or repeatedly adding AOS event listeners. See the [AOS project](https://github.com/michalsnik/aos/tree/v2).
